# 代码阅读与分析原则 (Code Reading & Analysis Guidelines)

在当前工作区中执行任何分析、排查、重构或编码任务时，必须严格遵守以下准则：

## 1. 代码读取能力优化，减少无效代码读取
- **杜绝大文件通篇阅读**：调用文件读取工具时，严禁无限制阅读整个文件，必须使用 `StartLine` 和 `EndLine` 将范围控制在 50~100 行以内的关键方法切片。
- **排除干扰目录**：严禁在 `build/`、`.gradle/`、`dist/`、`.idea/`、二进制文件或中间件缓存目录中进行全文检索或阅读。
- **目标达成即停**：一旦获取到支撑当前步骤所需的接口契约、方法逻辑或字段属性，立即停止进一步代码读取，杜绝无意义的代码漫游。

## 2. 优先读取已有的有效信息来分析代码
- **技术文档优先**：在面对陌生模块或复杂逻辑前，优先阅读项目已有的技术文档（如 `项目技术分析报告.md`、`README.md`、`CHANGELOG.md`），站在已有架构总结与设计时序图的肩膀上分析。
- **配置与清单优先**：平台组件与扩展点优先通过 `plugin.xml`、`build.gradle` 了解模块边界与外部依赖。
- **提交历史优先**：对关键设计决策或历史遗留问题，优先使用 `git log -S` / `git log -L` 查询演进历史与前序作者意图。

## 3. 由点到面渐进式分析，严禁全部读取 (Point-to-Surface)
- **锚点定位 (Point)**：使用高精准针对性搜索（如 `git grep` 关键方法、注解或异常符号）直接定位问题核心行，杜绝从根目录顺次通读。
- **调用切片 (Line)**：从锚点出发，仅沿主干调用链单向追踪直接调用者（Caller）与直接被调用者（Callee），不展开旁支。
- **最小边界 (Surface)**：仅在需要明确类生命周期、并发状态或继承约束时，才按需将范围适度扩展至类骨架，形成最小闭环上下文。
